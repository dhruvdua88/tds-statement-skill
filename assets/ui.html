TDS statement

Read the client's sheet, check it, write the statement file, and put together the folder for upload. Everything stays on this computer, and nothing is filed from here.

1 The source file and the period

The client's Excel or CSV. Messy is fine: title rows, totals and text amounts are handled.

2 What needs attention

Blockers stop a valid filing. Warnings need someone to look at them. If the deductor's own details were not in the sheet, download statement.json, fill them in, and upload it back here.

3 Write the statement file (TXT)

While anything is still outstanding, the file is named DRAFT so it cannot be mistaken for the real one.

4 Working paper

The workbook a reviewer signs, with the interest and late-fee working. Add the TDS payable ledger from Tally or Zoho to tie the return to the books (optional).

5 Correction statement optional

Only for a statement that has already been filed. The statement from step 1 counts as the one filed. Upload a corrected copy of statement.json and the PRN of the regular statement. The TRACES consolidated file cannot be read because its layout is not published, so type its hash in the box.

6 Official validation (FVU) optional here

This step needs Java and the department's File Validation Utility on this computer, plus the real Challan Status Inquiry (.csi) for the TAN. Every other step works without them. A statement counts as validated only once the utility has written a .fvu file, and this page says so only then.

7 The folder to hand over

The TXT, the working paper, the query list, the Form 27A figures and a checklist. The checklist starts with READY TO UPLOAD only when a .fvu exists and no blocker is left. A person does the upload.
